All internal APIs follow the standard response structure.

```json

    "success":false,
```

# 5. Internal Processing Rules

The following rules apply to all internal APIs.

- Internal APIs are not exposed publicly.
- Internal APIs are invoked only by backend services.
- All communication uses JSON.
- Internal processing is synchronous in the MVP.
- Future releases may replace synchronous communication with an event-driven architecture using Kafka or RabbitMQ.

# 3. Database Tables

## 3.1 Transaction Table

### Description

Stores every financial transaction received by the monitoring system.

---

### Table Name

```
transactions
```

---

### Columns

| Column | Data Type | Constraints | Description |
|---------|-----------|-------------|-------------|
| transaction_id | BIGINT | Primary Key, Auto Increment | Unique Transaction ID |
| sender_account_number | VARCHAR(30) | NOT NULL | Sender Account |
| receiver_account_number | VARCHAR(30) | NOT NULL | Receiver Account |
| amount | DECIMAL(15,2) | NOT NULL | Transaction Amount |
| currency | VARCHAR(5) | NOT NULL | Currency Code |
| transaction_type | VARCHAR(30) | NOT NULL | Transaction Type |
| description | VARCHAR(255) | NULL | Transaction Description |
| status | VARCHAR(20) | NOT NULL | SUCCESS / FAILED |
| transaction_datetime | DATETIME | NOT NULL | Transaction Time |

---




## 3.2 Alert Table

### Description

Stores alerts generated by the Rule Engine.

---

### Table Name

```
alerts
```

---

### Columns

| Column | Data Type | Constraints | Description |
|---------|-----------|-------------|-------------|
| alert_id | BIGINT | Primary Key, Auto Increment | Alert Identifier |

```
rules
```

# 4. Entity Relationships

Transaction

1

↓

Many

Alerts

Many

↓

1

Rule

Relationship Summary

- One transaction may generate zero or many alerts.
- Every alert belongs to exactly one transaction.
- Every alert is generated by exactly one rule.




# 5. Constraints

## Transaction Table

- Amount must be greater than zero.
- Sender Account is mandatory.
- Receiver Account is mandatory.

---

## Alert Table

- Alert must reference an existing transaction.
- Status must be one of:

```
OPEN
ACKNOWLEDGED
INVESTIGATING
CLOSED
DISMISSED
```

---

## Rule Table

- Rule Name must be unique.
- Threshold Amount must be greater than zero.
